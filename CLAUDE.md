# WhatsApp AI-агент — контекст проекта

ИИ, который подключается к диалогам в WhatsApp через Wazzup и общается с клиентами
от номера компании — только там, где разрешено правилами. Работает поверх
существующей связки Wazzup + amoCRM, ничего не заменяя.

Владелец — не программист. Объясняй изменения простым языком, без жаргона.
Интерфейс, комментарии и сообщения об ошибках — на русском.

## Стек

Python 3.12, FastAPI, SQLite, ванильный JS без сборки. Никаких npm и бандлеров:
фронтенд — два самодостаточных HTML-файла. Не предлагай переход на React
или добавление сборки без явной просьбы.

## Устройство

```
app/config.py      настройки из .env
app/storage.py     SQLite: диалоги, сообщения, очередь задач, решения
app/accounts.py    аккаунты, пользователи, сессии, настройки, журнал
app/rules.py       движок правил, возвращает решение с трассировкой
app/wazzup.py      клиент Wazzup API v3 + разбор вебхуков
app/amo.py         клиент amoCRM (пока с моками)
app/llm.py         генерация ответа (stub / Anthropic)
app/pipeline.py    машина состояний и оркестрация
app/admin_api.py   REST админки
app/main.py        HTTP-слой, вебхуки, воркер
static/admin.html  панель управления
static/test.html   тестовый чат
deploy/            systemd, nginx, скрипты установки и обновления
```

## Инварианты — не ломать

1. **Вебхук отвечает 200 немедленно.** Обработка уходит в фон через
   `BackgroundTasks`. Требование Wazzup: при медленном ответе вебхуки теряются.
   Не добавляй синхронную работу в `wazzup_webhook`.

2. **`crmUserId` отличает ИИ от менеджера.** Все исходящие ИИ помечаются
   `settings.AI_CRM_USER_ID`. Исходящее с другим идентификатором означает, что
   вмешался человек — диалог переходит в `handed_off`, ИИ замолкает.
   Это защита от двух ответов на один вопрос. Не убирай.

3. **Правила проверяются дважды.** Первый раз при входящем, второй — в
   `send_reply` после паузы. За время паузы менеджер мог перехватить диалог.

4. **ИИ работает только внутри 24-часового окна WhatsApp.** Вне окна нужен
   платный шаблон, который ИИ отправлять не должен.

5. **Каждое решение возвращается с трассировкой** — списком проверок с
   результатом. Молчаливых отказов быть не должно: владелец должен видеть,
   какое правило сработало.

6. **Правила читаются из базы**, `rules.yaml` — только начальное значение при
   первом запуске. Провайдер подставляется в `rules.set_provider`.

7. **`MODE=mock` ничего не отправляет наружу.** Любой новый внешний вызов
   должен уважать `settings.is_mock`.

## Состояния диалога

```
sleeping  → armed → active
              ↓        ↓
           handed_off ←┘
```

`handed_off` возвращается в работу только вручную — из панели или API.

## Секреты

`.env` в `.gitignore` и никогда не попадает в репозиторий. Ключи Wazzup,
amoCRM и Anthropic живут только на сервере. Если увидишь ключ в коде или
в истории — предупреди владельца, что его нужно отозвать.

## Проверка изменений

Локально:

```bash
cp env.example.txt .env
uvicorn app.main:app --port 8000
```

Ручной прогон правил без отправки:

```bash
curl -s -X POST localhost:8000/test/preview \
  -H 'Content-Type: application/json' \
  -d '{"text":"позовите менеджера"}'
```

Автотестов пока нет. Если добавляешь логику в `rules.py` или `pipeline.py` —
предложи покрыть её тестами на pytest.

## Развёртывание

Сервер: Ubuntu, `/opt/wa-agent`, systemd-служба `wa-agent`, nginx с HTTPS.

```bash
sudo bash deploy/setup.sh домен.kz   # первичная установка
bash deploy/update.sh                 # обновление после git pull
journalctl -u wa-agent -f             # логи
```

## Что в работе

- amoCRM пока на моках (`app/amo.py`), нужен живой OAuth
- база знаний хранится, но без векторного поиска — при росте нужен RAG
- уведомлений в Телеграм ещё нет
- логика дожима внутри окна описана в правилах, но не реализована
- слот вебхуков в Wazzup не подтверждён — до этого боевой запуск невозможен
