# WhatsApp AI-агент

ИИ, который подключается к диалогам в WhatsApp через Wazzup и общается с клиентами
от вашего номера — только там, где вы разрешили. Работает поверх существующей
связки Wazzup + amoCRM, ничего не заменяя.

## Запуск за две минуты

```bash
cp .env.example .env      # MODE=mock — наружу ничего не уходит
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Откройте http://localhost:8000 — тестовый чат.

Через Docker:

```bash
cp .env.example .env
docker compose up -d
```

## Тестовый чат

Три панели: слева сделка в amoCRM, по центру переписка, справа — решение ИИ
с полной трассировкой проверок.

Что стоит попробовать:

1. Написать как клиент — ИИ ответит через паузу (по умолчанию 8 секунд).
2. **Написать как менеджер, пока идёт обратный отсчёт** — ИИ замолчит.
   Это главная защита от коллизий: двух ответов на один вопрос не будет.
3. Поставить тег `отказ` — ИИ уйдёт в молчание, справа будет видно почему.
4. Сменить этап на «Счёт выставлен» — ИИ выключится по правилу этапов.
5. Добавить тег `ии` при запрещённом этапе — ручной тумблер перекроет правило.
6. Написать «позовите менеджера» — сработает передача человеку.

## Настройка поведения

Всё в `rules.yaml`. Файл читается на лету — правки применяются без перезапуска.

| Раздел | За что отвечает |
|---|---|
| `stages` | на каких этапах воронки ИИ работает |
| `stop_list` | кому нельзя писать никогда |
| `manual_switch` | теги-тумблеры для точечного включения |
| `schedule` | часы работы и что делать вне их |
| `limits` | лимит реплик, анти-флуд, окно 24 ч |
| `handoff` | когда передавать человеку |
| `amo_writeback` | что писать обратно в сделку |

## Переход в боевой режим

1. В `.env` поставить `MODE=live`, заполнить `WAZZUP_API_KEY` и `WAZZUP_CHANNEL_ID`.
2. Узнать `channelId`: `curl localhost:8000/setup/channels`
3. Проверить, свободен ли слот вебхуков: `curl localhost:8000/setup/webhooks`
4. Подписаться на вебхуки:

```bash
curl -X POST localhost:8000/setup/webhooks \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://ваш-домен/webhook/wazzup"}'
```

Домен должен быть с HTTPS и доступен извне. Для локальной проверки годится ngrok.

5. Для реальных ответов: `LLM_PROVIDER=anthropic` и ключ из console.anthropic.com.
   Ключ подписки Claude здесь не подойдёт — нужен именно API-ключ.

## Архитектура

```
Wazzup ──вебхук──► /webhook/wazzup ──► очередь (SQLite)
                        │                    │
                        └── 200 сразу        ▼
                                        движок правил
                                             │
                            ┌────────────────┼────────────────┐
                            ▼                ▼                ▼
                         молчать      передать человеку    ответить
                                             │                │
                                          amoCRM         LLM ─► Wazzup
```

Ключевые решения:

- **Ответ 200 немедленно**, обработка в фоне — требование Wazzup, иначе вебхуки теряются.
- **Пауза перед ответом** даёт менеджеру окно на перехват.
- **Повторная проверка правил** после паузы: за это время ситуация могла измениться.
- **`crmUserId`** отличает сообщения ИИ от ручных. Без него система отвечала бы
  поверх менеджера.
- **Очередь в SQLite** переживает перезапуск сервера.

## Структура

```
app/config.py     настройки из .env
app/storage.py    SQLite: диалоги, сообщения, очередь, решения
app/rules.py      движок правил, возвращает решение с трассировкой
app/wazzup.py     клиент Wazzup API + разбор вебхуков
app/amo.py        клиент amoCRM
app/llm.py        генерация ответа (stub / Anthropic)
app/pipeline.py   машина состояний и оркестрация
app/main.py       HTTP-слой и API тестовой консоли
rules.yaml        настройки поведения
static/test.html  тестовый чат
```

## Установка на сервер

Нужен Ubuntu или Debian с доступом по SSH и домен, указывающий на его IP.

```bash
git clone https://github.com/ВАШ_АККАУНТ/wa-agent.git
cd wa-agent
sudo bash deploy/setup.sh ваш-домен.kz
```

Скрипт ставит зависимости, создаёт службу systemd, настраивает nginx,
выпускает HTTPS-сертификат и включает ежедневный бэкап базы.
Пароль администратора генерируется и печатается в конце — сохраните его.

Обновление после изменений в репозитории:

```bash
cd /opt/wa-agent && bash deploy/update.sh
```

Полезное:

```bash
systemctl status wa-agent     # состояние
journalctl -u wa-agent -f     # логи в реальном времени
systemctl restart wa-agent    # перезапуск
```

### Секреты

`.env` лежит только на сервере и в репозиторий не попадает — он в `.gitignore`.
Ключи Wazzup, amoCRM и Anthropic вписываются прямо на сервере:

```bash
sudo nano /opt/wa-agent/.env
sudo systemctl restart wa-agent
```
